## 1. 6결이 무엇인가

### 사실

- 정식 이름 「6결 성향 지도」. 친구끼리 노는 **비상업 팬 테스트**(먼작귀 캐릭터 기반)로, 48문항에 답하면 가장 닮은 캐릭터·축별 점수·성격 카드를 받아 공유해요. 검색 제외(noindex), 광고·후원·유료 없음. 상태 완료(최근 갱신 2026-09-27).
- 문항: 48문항, 7점 척도, 축당 8문항(높은 극 4·낮은 극 4), 한 화면 1문항, 같은 축 3연속·같은 방향 4연속 금지 순서 섞기(시드 기반). 12·24·36번에 응원 문구.

### 6축 [사실]

| --- | --- | --- | --- | --- |
| 용기 스위치(nerve) | C 조심조심 | D 일단직진 | 두려운 상황의 첫 반응 | 신경성 반대 |

| 챙김 성향(care) | M 마이페이스 | K 먼저챙김 | 함께 있을 때 우선순위 | 원만성 |

### 계산식 [사실, `public/assets/engine.js`]

1. 축 점수: 높은 극 문항은 응답 그대로, 낮은 극은 8−응답. 합(8~56) → `floor((100×(합−8)+24)/48)` 정수 0~100(도달 가능 값 49개). (engine.js 12-15행)
2. 구간: 0~42 낮음 / 43~57 균형 / 58~100 높음. 6글자 코드는 높은 극 DVGKWR·낮은 극 CQHMOL 대문자, 균형은 소문자. (22-30행)
3. 매칭: 사용자 점수를 사전 규준 μ=[50,50,54,56,50,52], σ=15로 표준화, 캐릭터 좌표는 캐릭터끼리 표준화, **가중 코사인**(챙김 축 가중치 0.7). 세기 계수 k=min(1, R/0.8), 급한 응답 플래그 f=0.7, 표시 %=floor(50+50·cos·k·f+0.5). R<0.5이면 **골고루형**. 동점은 코사인→최대 이탈 축→고정 순서. (39-75행)
4. 1·2위 차 ≤2%p면 하이브리드 배지, 가장 먼 캐릭터는 정반대 친구. (67-72행)
5. 급한 응답 플래그: 48개 중 같은 답 40개 이상 또는 문항당 평균 1.2초 미만. (128-134행)
6. 궁합: 두 6축 벡터 RMS 거리 d → `floor(100·exp(−d²/800)+0.5)`, 차이가 가장 큰 축을 대화 포인트로. (121-126행)
7. 시뮬레이션(실제 사람 아님): 현실적 응답 캐릭터별 4.4~15.5%(JS 2만 명), 12/12 자기 좌표 자기 1위, 최소 각도 49.8°, 재검사 1위 유지 약 42%(3위 안 약 75%).

### 결과 카드 [사실]

캐릭터 고정 문단 · 가장 뚜렷한 두 축 설명 · 닮은 결 2개/다른 결 1개 · 1~3위 % · 6축 막대 · 6글자 코드 · 찰떡/정반대 친구 · 공유(기기 공유 → 링크 복사 → 1080×1920 이미지 저장) · 궁합 링크. 결과 링크 `/r/{캐릭터}?d={15자}`, 궁합 `/duo?a=&b=`.

## 2. 지난 결정에서 옮길 교훈

### 사실 — 기록된 교훈

- 재미용 결과도 쏠림·확신 과잉을 숫자로 먼저 봐야 설계가 달라진다. 공개 전에 친구 3~5명 독립 평정과 작은 샘플 테스트를 먼저 했어야 했다(근거가 시뮬레이션뿐).
- 사이트 문구를 다 없애더라도 비공식 고지 한 줄은 남겼어야 했다.
- 결과·식별 정보 없이도 사용량을 셀 수 있고, sendBeacon 같은 전송 방식 하나가 결과 링크 유출 경로가 될 수 있다. 옵트인 카드를 없앤 이유는 기록에 없다(남겼어야 함).
- 48문항은 한국 바이럴 표준(11~12문항)의 약 4배라 완주율 위험.
- 출시 전 5관점 검토 39건 중 36건 반영, 이후 최종 검토 24건 중 15건 수정.

### 의견

- 새 미니앱에 바로 옮길 교훈은 세 가지라고 본다: (1) 공개 전에 사람 파일럿(작은 표본)으로 실제 분포를 먼저 본다, (2) 결정 이유를 행으로 남긴다(이유 없는 변경 금지), (3) 문항 수는 앱인토스 맥락에서 더 짧게 다시 정한다.

## 3. v1 배포 사실과 지표

### 사실

- 2026-09-27 공개: Cloudflare Worker + 정적 파일, D1, 사용자 지정 도메인. 자동 테스트 18개로 시작해 같은 날 97개까지 늘었어요.
- **실제 지표 없음**: 사람 대상 응답 기록 없음("문항은 아직 사람에게 풀려 보지 않았습니다"), 실제 방문자 수 미확인.

### 의견

- 쓸 수 있는 숫자는 시뮬레이션 분포와 테스트 개수뿐이다. 새 미니앱 기획서에 "사용자 반응"을 근거로 쓰면 안 된다.

## 6. 기술 스택과 앱인토스 WebView SDK 3.x와의 거리

### 사실

- 프레임워크·번들러 **없음**: 순수 HTML + ES 모듈 JS(app.js 703줄, engine.js 233줄, ui.js 271줄 등).
- Node ≥22 빌드 스크립트, 테스트는 `node --test`. 호스팅은 Cloudflare Workers static assets + D1 + Analytics Engine + rate limit.

### 의견

- **엔진 계층은 가깝고, 화면·공유·배포 계층은 멀다.** engine.js는 React/Vite 프로젝트에 파일 하나로 넣을 수 있다. app.js는 문자열 템플릿으로 DOM을 직접 그려서 사실상 새로 써야 한다.
- 바뀌어야 할 것: 정적 결과 페이지·OG 미리보기 → 토스 공유 링크/딥링크, 기기 공유 → SDK 공유, 보안 헤더·noindex → 해당 없음, 계수기·D1 → 필요 시 별도 서버(CORS) 또는 토스 제공 분석, 토스 디자인 가이드(TDS) 적용. SDK 3.x 세부는 [toss-official-2026-11-27.md](toss-official-2026-11-27.md)에서 다시 확인했어요.
