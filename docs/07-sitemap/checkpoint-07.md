## 1. 앞서 승인된 것 중 이번 작업이 바꾸거나 빠뜨리는 것

**빠뜨린 것: 없어요.** 03 흐름 16개의 단계 161개마다 SCR 칸을 더했고, 화면을 보여 주는 단계는 모두 SCR(또는 SCR의 상태)을 가리켜요. 화면이 없는 단계는 "서버", "운영(저장소)", "토스(…)"로 적었어요(`scripts/check-screens.py` 통과, 3절).

**바꾼 것(뜻은 그대로):** 03 흐름 파일 16개의 단계 표에 SCR 칸 하나를 더했어요. 03 README가 "화면 ID(SCR)는 07 사이트맵 뒤에 단계에 더해요"라고 정해 둔 일이에요. 단계의 이름·하는 일·REQ는 바꾸지 않았어요.

**08에서 찾은 것:** FL-012 "지워졌어요 안내"의 "처음 화면으로 돌아가요"를 바꾸자는 제안은 08 질문 2예요. 07 구조와는 상관없어요.

## 4. 체크포인트 질문

**질문 1. 화면 15개(SCR-001~015)의 내비게이션 구조를 승인할까요?** (DDD 변경 아님)

뿌리는 진입 확인(SCR-001)이고, 초대 링크 없이 열면 홈(SCR-002) 가지(테마 고르기 → 방 정보 적기, 지난 카드 → 자세히, 내 데이터 지우기, 약관 두 개), 초대 링크나 내 방 목록에서 방을 고르면 방 소개(SCR-005) 가지(닉네임 정하기, 문항, 내 결과, 합의 카드, 최종 카드)로 가요.

1. 승인해요. 08 화면 정의와 09 목업은 이 15개 화면을 기준으로 해요. **← 추천**
2. 고칠 곳이 있어요(SCR 번호와 고칠 점을 알려 주세요).

- 추천 이유: 화면을 보여 주는 흐름 단계가 모두 화면에 연결되고, 같은 화면의 다른 상태는 08로 모아 화면 수가 15개로 작아요. 방 코드가 주소에 없어 DEC-025를 지키고, 초대 링크로 들어온 첫 화면의 뒤로가기가 미니앱을 닫아요.
- 반대 근거: 실제로 누른 화면이 없어 화면 사이 이동이 어색한지는 09 목업에서야 알 수 있어요. 또 S-4처럼 합의 카드와 응답 현황을 한 화면에 두면 방장 화면에 버튼이 많아져(카드 저장, 단톡방에 보내기, 지금 마감하기) 목업에서 나눠야 할 수도 있어요. 그때는 화면이 하나 늘어요(SCR-016).
