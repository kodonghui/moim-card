## 3. 방장 화면(SCR-009) 버튼 수와 문구 길이 (DEC-028)

- 정상 상태, 방장: 버튼 3개(카드 저장, 단톡방에 보내기, 지금 마감하기)와 글자 링크 2개(새로고침, 내 모임 성향 다시 보기). 참여자는 지금 마감하기가 없어 버튼 2개예요.
- 응답 1명(빈 상태), 방장: 버튼 2개(친구 부르기, 꺼진 지금 마감하기)와 "2명 이상이 답하면 마감할 수 있어요".
- 가장 긴 글자(모임 이름 20자, 문항 40자, 선택지 30자, 다음 행동 52자, 닉네임 10자)는 360px에서 두세 줄로 줄바꿈하고, 단어가 중간에 끊기거나 넘치지 않아요(검사 결과 4절).

## 5. 사용자님께 드릴 질문

**질문 1. 어느 시안으로 갈까요?** (고른 방향으로 나머지 12개 화면을 그려요. DDD 변경 아님)

1. 시안 A(토스처럼 깔끔하게). **← 추천**
2. 시안 B(모임 카드처럼 따뜻하게).
3. A를 바탕으로 하고, 합의 카드만 B의 카드 한 장 모양으로 해요.

- 추천 이유: 토스 앱 안에서 다른 화면과 어색함이 없고, 실제로 만들 때 TDS 컴포넌트(파란 버튼, 목록)를 거의 그대로 써 검수와 개발이 가장 쉬워요. 글자 대비와 버튼 수는 두 시안이 같아요.
- 반대 근거: 단톡방에 보내거나 사진으로 저장한 카드가 B보다 밋밋해 친구가 눈여겨보지 않을 수 있어요. 카드가 이 앱의 핵심이라면 3번(카드만 B 모양)이 나을 수 있고, B의 주황색은 토스 파란 버튼과 섞여 보이지 않게 직접 만든 버튼이 더 필요해요.

**질문 2. 방장 화면의 버튼 수와 문구 길이는 이대로 괜찮을까요?** (DEC-028의 요청. 합의 카드 아래 버튼 3개: 카드 저장, 단톡방에 보내기, 지금 마감하기)

1. 이대로 해요. **← 추천**
2. 줄여요: 카드 저장과 단톡방에 보내기를 버튼 하나("카드 보내기·저장")로 묶어요.

- 추천 이유: 세 버튼은 하는 일이 달라(저장, 공유, 마감) 묶으면 한 번 더 눌러야 해요. 마감 버튼은 방장에게만 보이고 아래쪽에 따로 있어 잘못 누르기 어렵고, 누르면 확인 창이 떠요.
- 반대 근거: 문항 8개 카드가 길어 버튼이 화면 맨 아래에 있어요. 360px 휴대폰에서는 카드를 끝까지 내려야 버튼이 보여요.
