# 모임 합의 카드(가칭): 요구사항 (02 PRD)

상태: 초안, **체크포인트 대기**(범위 고정). 체크포인트 질문은 [checkpoint-02.md](checkpoint-02.md)에 있어요. 입력은 [01 도메인 설계](../01-domain/domain.md)(CTX-001~006, TERM-001~042, 승인 main `9b5e401`)와 [00 조사](../00-research/)예요.

- 문장 형식: EARS(Easy Approach to Requirements Syntax, 요구사항 문장을 다섯 가지 틀 중 하나로 쓰는 방법). 틀은 항상(ubiquitous) · 사건(event, "~하면") · 상태(state, "~인 동안") · 원치 않는 일(unwanted, "~이면 … 하지 않아야") · 선택 기능(optional, "~를 넣는 경우")이에요. 요구사항 하나에 "해야 해요"는 하나예요.
- 우선순위: MoSCoW(Must 꼭, Should 되도록, Could 여유가 있으면). 첫 버전 범위는 Must와 Should예요.
- 유형: 기능, 비기능. 비기능은 비고 칸에 "측정:"으로 측정 방법을 적어요.
- 상태: `active`(이 초안에서 정함) · `질문 대기`(체크포인트 질문의 답에 따라 문장이 바뀜, 지금 문장은 추천안) · `removed`/`deferred`(뒤에서 빠지면 번호를 다시 쓰지 않고 표시만 바꿈).
- 출처 약어: **제안** = [제품 방향 제안](../00-research/proposal-2026-11-27.md) · **토스** = [토스 공식 자료 노트](../00-research/toss-official-2026-11-27.md)(절 번호) · **01** = [domain.md](../01-domain/domain.md)의 컨텍스트 표·핫스팟 · **DEC** = [결정 기록](../records/decisions.md) · **AI** = 이 초안에서 AI가 정한 것(근거는 비고).
- 시스템 이름: "미니앱"은 화면과 서버를 함께 말하고, "서버"는 Cloudflare Workers + D1 쪽만 말해요.
