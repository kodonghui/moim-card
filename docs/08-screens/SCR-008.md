# SCR-008 내 결과

경로 `/room/result` · 누가: 참여자(응답 뒤) · 흐름: FL-003, FL-004, FL-007, FL-010 · SPEC: SPEC-012, SPEC-022, SPEC-024

목적: 응답을 낸 참여자가 다른 사람을 기다리지 않고 내 모임 성향을 보고, 카드 보기·친구 부르기·알림 받기 중 하나로 이어 가요. (FL-004, FL-010)

## 데이터

| 데이터 | 출처 |
| --- | --- |
| 내 모임 성향: 한 줄 설명, 축(계획 속도, 지출 우선순위, 일정 변경 반응)마다 낮음·균형·높음 | 막 제출했으면 SCR-007이 받은 API-007 응답의 `profile`(메모리), 그 밖에는 API-008 `PersonalProfile` |
| 방 상태, 응답 완료 수/인원, 기준 시각 | API-004 `status`, `submittedCount`, `partySize`, `asOf` |
| 내 닉네임 | 메모리(없으면 표시를 빼요) |
| 알림 동의 결과 | SDK `Notification.requestAgreement`(`newAgreement`·`alreadyAgreed`·`agreementRejected`). 지원 여부는 `isSupported()` |
| 알림 신청 결과 | API-011 `SubscriptionResult` |

## 동작

| 동작 | 결과 | 실패 |
| --- | --- | --- |
| [카드 보기] | 열린 방이면 SCR-009, 마감된 방이면 SCR-010 | 없음(화면 이동만) |
| [친구 부르기] | 초대 링크로 토스 공유 시트를 열어요(SPEC-022). 끝나면 이 화면 그대로 | "링크를 만들지 못했어요"와 [다시 시도]. 낮은 버전 → G-10 |
| [알림 받기] | 지원하면 토스 알림 동의문을 띄워요. `newAgreement`·`alreadyAgreed`면 새 인증 코드와 함께 API-011 → #notify-done | 지원 안 함 → #notify-update. 거절 → 아무것도 바꾸지 않음. 서버 실패 → 아래 응답 표 |
| [새로고침] | API-004를 다시 불러요 | #error |

## 상태

| 상태 | 사용자가 보는 것과 할 수 있는 것 | 이 응답에서 |
| --- | --- | --- |
| SCR-008#normal | "○○ 님의 모임 성향"과 한 줄 설명. 축마다 이름과 낮음·균형·높음 세 칸 중 하나 표시(점수 숫자 없음). 그 아래 "4명 중 2명 답했어요 · 오후 3시 5분 기준". 버튼: [카드 보기](주 버튼), [친구 부르기], [알림 받기](열린 방일 때만) | API-008#200, API-004#200 |
| SCR-008#loading | 같은 배치에 회색 자리 표시(G-8). 알림 신청 중에는 [알림 받기]에 진행 표시(G-7) | API-008 요청 중, API-011 요청 중 |
| SCR-008#error | 성향을 불러오지 못함: "잠시 뒤 다시 해 주세요"와 [다시 시도]. 알림 신청 실패: [알림 받기] 아래 "알림을 신청하지 못했어요"와 [다시 시도]. 404: "이 방은 없거나 보관 기간이 지났어요"와 [방 만들기] | API-008#404, API-008#default, API-004#404, API-004#default, API-011#400, API-011#404, API-011#429, API-011#503, API-011#default |
| SCR-008#permission | 응답 전: SCR-007로. 참여자가 아님: SCR-005로. G-1, G-2 | API-008#403, API-011#403, API-008#401, API-004#401, API-011#401, API-004#403 |
| SCR-008#stale | 방이 마감됨: 맨 위 "모두 답해서 카드가 완성됐어요"(또는 "방이 마감됐어요"), [알림 받기]가 사라지고 [카드 보기]가 SCR-010으로 가요. 돌아오면 다시 불러와요(G-9) | API-004#200(`closed`), API-011#409(room_closed), 막 제출한 응답의 `roomStatus: closed`(SCR-007) |
| SCR-008#notify-update | [알림 받기] 아래 "토스 앱을 업데이트하면 알림을 받을 수 있어요"(G-10). 신청은 생기지 않아요 | `isSupported()`가 false(토스 앱 5.255.0 미만) |
| SCR-008#notify-done | [알림 받기] 자리에 "알림을 신청했어요. 친구가 답을 마치면 알려 드려요"(이미 신청했으면 "이미 알림을 신청했어요") | API-011#201, API-011#200 |

## 해당하지 않는 상태

- empty: 응답을 냈으면 성향이 늘 있어요. 묶인 문항이 없는 축은 빼고 보여 줘요(SPEC-012).

## 경우의 종류

| 종류 | 화면에 보이는 것 |
| --- | --- |
| 접근 | 응답 전이면 SCR-007. [알림 받기]는 응답 뒤에만 있어요(REQ-061) |
| 대상 | 없는 방 → 404 안내. 내 데이터를 지운 뒤에는 볼 수 없어요(G-1 뒤 새 사용자라 SCR-005) |
| 상태 변화 | 마감 → #stale |
| 반복 | 알림을 두 번 신청해도 신청은 하나(200 → #notify-done) |
| 한도 | G-3 |
| 외부 | 동의 거절은 아무것도 바꾸지 않음. 토스 API 실패 503은 #error, 성향은 그대로 |
| 노출 | 점수 숫자·유형 이름·다른 검사 이름 없음(SPEC-012). 식별키·암호문은 화면과 로그에 없음 |
| 화면 상태 | 일곱 상태 모두 360px·430px 와이어프레임 |
| 해당 없음 | 입력, 동시성, 빈 결과, AI 답 |

## 규칙

- 알림 동의문은 사용자가 [알림 받기]를 누를 때만 띄워요. 진입 직후·제출 직후 자동으로 띄우지 않아요(REQ-066, SPEC-024).
- 초대 링크로 들어온 참여자(이미 답함)에게는 이 화면이 첫 화면일 수 있고, 그때 뒤로가기는 미니앱을 닫아요.
