# SCR-009 합의 카드

경로 `/room/card` · 누가: 참여자(응답 뒤, 열린 방). 마감하기는 방장만 · 흐름: FL-006, FL-007, FL-008 · SPEC: SPEC-016, SPEC-017, SPEC-019, SPEC-020, SPEC-022

목적: 응답을 낸 참여자가 열린 방의 중간 카드와 응답 현황을 보고, 카드를 저장하거나 단톡방에 보내요. 방장은 응답 완료가 2명 이상이면 일찍 마감해요. (FL-006, FL-008)

## 데이터

| 데이터 | 출처 |
| --- | --- |
| 카드: 단계, 기준 응답 수, 문항마다 질문·선택지·분류·선택지별 수·문구, 다음 행동 | API-009 `Card`(`stage`, `basedOnCount`, `items[]`, `nextAction`) |
| 응답 현황: 인원, 응답 완료 수, 내 역할, 기준 시각 | API-004 `partySize`, `submittedCount`, `myRole`, `asOf` |
| 마감 결과 | API-010 `CloseResult`(`roomStatus`, `closeReason`, `card`) |
| 카드 이미지 | 화면의 카드 부분을 PNG(1080px 너비)로 만들어 SDK `File.saveBase64`(SPEC-020) |
| 초대 링크 | SDK `Share.createLink`(방 코드만, SPEC-022) |

## 경우의 종류

| 종류 | 화면에 보이는 것 |
| --- | --- |
| 접근 | 응답 전에는 카드·다른 사람의 응답을 보여 주지 않아요(REQ-014). 마감 버튼은 방장에게만 |
| 대상 | 없는 방 → 404 안내 |
| 상태 변화 | 그사이 마감 → SCR-010. 2명 미만 마감 거절 → #stale |
| 반복 | 마감 버튼이 꺼지고, 다시 보내도 마감은 한 번(200 `already-closed`). 카드 저장은 두 번 누르면 파일 두 개(막지 않음, SPEC-020) |
| 동시성 | 자동 마감과 방장 마감이 겹치면 먼저 커밋한 쪽 하나. 화면은 200의 카드를 그대로 보여 줘요 |
| 한도 | G-3 |
| 외부 | 저장·공유 실패는 그 버튼 아래 안내만, 카드는 그대로 |
| 노출 | 닉네임·누가 무엇을 골랐는지·순위·점수가 카드와 이미지에 없어요. 이미지에 방 코드 없음 |
| 빈 결과 | #empty |
| 화면 상태 | 문항 8개 카드는 세로로 길어 스크롤해요. 일곱 상태 모두 360px·430px 와이어프레임 |
| 해당 없음 | 입력, AI 답 |

## 규칙

- 카드의 분류와 수는 서버 결과를 그대로 보여 주고 화면이 다시 계산하지 않아요(SPEC-013).
- "인원 n명 중 m명 답했어요"는 방 소개에도 보이는 수라 방장이 아닌 참여자에게도 보여요(SPEC-006, SPEC-017, R-10). 마감 버튼만 방장 전용이에요.

## 목업

- 목업: [design/mockups/mockup.html](../../design/mockups/mockup.html)에서 SCR-009 화면을 고르면 상태가 모두 나와요(09, DEC-033). 토큰은 [design/base.tokens.json](../../design/base.tokens.json)이에요.
- 합의 카드는 카드 한 장 모양이에요(DEC-033): 연한 머리 띠에 모임 이름·테마·"n명 기준 중간 카드", 다음 행동 상자, 분류마다 색 띠와 이름표(조율해요 주황, 모두 좋아요 초록, 누구나 괜찮아요 회청색). 이 색들은 카드 안에서만 써요.
- 카드 아래 [카드 저장]·[단톡방에 보내기] 두 버튼, 그 아래 구분선과 "방장에게만 보여요", [지금 마감하기](방장만), 글자 링크 [내 모임 성향 다시 보기]. 방장 버튼 3개는 이대로 둬요(DEC-034).
- 카드 이미지 저장(SPEC-020)은 이 카드 한 장(머리 띠부터 마지막 분류까지)을 그대로 PNG로 만들어요.
