# SCR-007 문항

경로 `/room/questions` · 누가: 참여자(응답 전, 열린 방) · 흐름: FL-002, FL-003, FL-004, FL-007 · SPEC: SPEC-010, SPEC-011, SPEC-018, SPEC-022, SPEC-009

목적: 방에 고정된 문항 8개에 하나씩 답해 제출하고 내 결과(SCR-008)로 가요. 방장은 이 화면에서 친구도 불러요(DEC-005). (FL-004, FL-002)

## 데이터

| 데이터 | 출처 |
| --- | --- |
| 문항 8개: 질문, 선택지 A·B | API-006 `questions[]`(`position`, `prompt` 최대 40자, `optionA`·`optionB` 최대 30자) |
| 고른 답(제출 전) | 기기 저장소(SPEC-009, SPEC-010). 제출이 성공하면 지워요 |
| 내 닉네임 | 이 방에 들어올 때 적은 값(메모리). 없으면 표시를 빼요 |
| 제출 결과: 방 상태, 응답 완료 수, 카드 단계, 전환 표시, 내 모임 성향 | API-007 `SubmitResult` |
| 초대 링크 | SDK `Share.createLink`(방 코드만, SPEC-022) |

## 동작

| 동작 | 결과 | 실패 |
| --- | --- | --- |
| 선택지 누름 | 그 문항에 A·B·"상관없어요" 중 하나만 표시되고 기기에 저장돼요. 맨 위 "8개 중 5개 골랐어요"가 늘어요 | 없음(기기 안 동작) |
| [제출하기] | 8개를 다 골랐으면 API-007(요청 ID 함께). 201이면 `logConversion`이 true일 때 `Analytics.log`(`interim_card_created`)를 한 번 부르고 SCR-008로 가요(기록 바꿔 끼움) | 다 고르지 않음 → 첫 빈 문항으로 스크롤하고 "아직 고르지 않았어요". 서버 실패 → 아래 응답 표 |
| [친구 부르기] | 초대 링크를 만들어 토스 공유 시트를 열어요. 보내든 취소하든 이 화면 그대로 | "링크를 만들지 못했어요"와 [다시 시도]. 낮은 토스 앱 버전 → "토스 앱을 업데이트하면 링크를 보낼 수 있어요"(G-10) |

## 상태

| 상태 | 사용자가 보는 것과 할 수 있는 것 | 이 응답에서 |
| --- | --- | --- |
| SCR-007#normal | 맨 위에 붙은 "8개 중 5개 골랐어요"와 "○○ 님으로 참여 중". 문항 8개가 한 화면에 차례로(문항마다 질문과 선택지 버튼 3개). 맨 아래 붙은 [제출하기](8개를 다 고르면 켜짐)와 그 위 [친구 부르기] | API-006#200 |
| SCR-007#loading | 문항 카드 자리에 회색 자리 표시 3개, 진행 표시 "8개 중 0개"(G-8). 제출 중에는 [제출하기]에 진행 표시, 선택지가 꺼져요(G-7) | API-006 요청 중, API-007 요청 중 |
| SCR-007#error | 문항을 불러오지 못함: "잠시 뒤 다시 해 주세요"와 [다시 시도]. 제출 실패: [제출하기] 위에 "제출하지 못했어요. 고른 답은 그대로예요"와 [다시 시도](같은 요청 ID). 400 `validation_failed`: `positions`의 첫 문항으로 스크롤, "아직 고르지 않았어요". 404: "이 방은 없거나 보관 기간이 지났어요"와 [방 만들기]. 링크 실패: "링크를 만들지 못했어요" | API-006#default, API-006#404, API-007#400, API-007#404, API-007#429, API-007#default |
| SCR-007#permission | 참여자가 아님: SCR-005로 가요(기록 바꿔 끼움). G-1(고른 답 그대로), G-2 | API-006#403(not_participant), API-007#403(not_participant), API-006#401, API-007#401 |
| SCR-007#stale | 방이 그사이 마감: SCR-010으로 가고 "방이 그사이 마감됐어요"(W-6), 고른 답은 지워요. 이미 답함: SCR-008로 가고 "이미 답했어요" | API-006#409, API-007#409(room_closed, already_submitted) |

## 해당하지 않는 상태

- empty: 방에는 늘 문항 8개가 고정돼 있어요(API-006 `questions`는 8개). 8개가 아니면 앱 버그로 G-5예요.

## 경우의 종류

| 종류 | 화면에 보이는 것 |
| --- | --- |
| 접근 | 참여자가 아니면 SCR-005. 확인 안 됨은 G-1 |
| 입력 | 다 고르지 않으면 제출하지 않고 첫 빈 문항으로(REQ-012) |
| 대상 | 없는 방 → 404 안내 |
| 상태 변화 | 마감·이미 답함 → #stale |
| 반복 | [제출하기]가 꺼지고, 다시 보내도 응답은 하나(같은 요청 ID) |
| 동시성 | 인원의 마지막 자리를 두 사람이 동시에 내면 늦은 사람은 409 `room_closed`(#stale) |
| 한도 | G-3 |
| 외부 | 제출 실패는 고른 답 그대로. 공유 실패는 이 화면의 다른 부분에 영향 없음 |
| 노출 | 다른 참여자의 답·닉네임이 없어요. 전환 기록에 방 코드·사용자 ID 없음 |
| 화면 상태 | 40자 질문과 30자 선택지는 360px에서 줄바꿈. 다섯 상태 모두 360px·430px 와이어프레임 |
| 해당 없음 | 빈 결과, AI 답 |

## 규칙

- 문항 8개를 한 화면에 차례로 보여 주고, 이전·다음 버튼을 두지 않아요(W-2).
- 뒤로가기로 나가도 고른 답은 기기에 남아 다시 열면 이어서 골라요(SPEC-009).
- 선택지는 A, B, "상관없어요" 세 개이고, "상관없어요"를 덜 중요해 보이게 그리지 않아요.
