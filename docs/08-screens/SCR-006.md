# SCR-006 닉네임 정하기

경로 `/room/join` · 누가: 참여자가 아닌 확인된 사용자(열린 방, 8명 미만) · 흐름: FL-003 · SPEC: SPEC-007, SPEC-008

목적: 이 방에서 쓸 닉네임을 적고 입장해 문항(SCR-007)으로 가요. (FL-003)

## 데이터

| 데이터 | 출처 |
| --- | --- |
| 모임 이름 | SCR-005가 받은 API-004 결과(메모리) |
| 입장 결과: 역할, 답했는지 | API-005 `JoinResult`(`myRole`, `mySubmitted`) |
| 금칙어 목록 | 번들 안 목록(SPEC-008) |

## 동작

| 동작 | 결과 | 실패 |
| --- | --- | --- |
| 닉네임 적기 | "0/10" 글자 수. 칸을 떠날 때 규칙을 봐요 | 규칙 밖 → 칸 아래 이유, 값은 그대로 |
| [들어가기] | API-005(요청 ID 함께) → 201이면 SCR-007. 200(이미 참여자)이면 답하기 전 SCR-007, 답했으면 SCR-008. 이 화면과 SCR-005 기록은 바꿔 끼워요 | 400 이유, 409 8명·마감, 404 없는 방, 429·오류 다시 시도 |

## 상태

| 상태 | 사용자가 보는 것과 할 수 있는 것 | 이 응답에서 |
| --- | --- | --- |
| SCR-006#normal | "제주 3박에서 쓸 닉네임을 적어 주세요", 닉네임 칸, "닉네임은 이 방에서 나만 봐요", [들어가기](규칙에 맞을 때 켜짐) | |
| SCR-006#loading | [들어가기]에 진행 표시, 칸과 버튼이 꺼져요(G-7) | API-005 요청 중 |
| SCR-006#error | 400: 칸 아래 "닉네임은 1~10자로, 쓸 수 없는 말이 있어요". 409 8명: "이 방은 8명이 다 찼어요", [들어가기]가 꺼지고 [방 만들기]. 404: "이 방은 없거나 보관 기간이 지났어요"와 [방 만들기]. 그 밖: G-3·G-4 | API-005#400, API-005#409(room_full), API-005#404, API-005#429, API-005#default |
| SCR-006#permission | G-1(적은 닉네임 그대로), G-2 | API-005#401, API-005#403 |
| SCR-006#stale | 방이 그사이 마감됐어요: SCR-010으로 가고 맨 위에 "방이 그사이 마감됐어요"(W-6) | API-005#409(room_closed) |

## 해당하지 않는 상태

- empty: 적는 화면이라 빈 목록이 없어요.

## 응답과 상태

| 응답 | 코드 | 상태 | 화면이 하는 일 |
| --- | --- | --- | --- |
| API-005#201 | joined | 없음(다음 화면) | SCR-007로 가요 |
| API-005#200 | already-member | 없음(다음 화면) | `mySubmitted`에 따라 SCR-007 또는 SCR-008 |
| API-005#400 | validation_failed, invalid_request | error | 칸 아래 이유. `invalid_request`는 G-5 |
| API-005#401 | unauthenticated | permission | G-1 |
| API-005#403 | origin_not_allowed | permission | G-2 |
| API-005#404 | room_not_found | error | 없는 방 안내와 [방 만들기] |
| API-005#409 | room_full, room_closed, idempotency_conflict | error 또는 stale | `room_full` → #error. `room_closed` → #stale(SCR-010). `idempotency_conflict` → G-6 |
| API-005#429 | rate_limited | error | G-3 |
| API-005#default | internal, route_not_found, method_not_allowed | error | G-4. 다시 시도는 같은 요청 ID |

## 경우의 종류

| 종류 | 화면에 보이는 것 |
| --- | --- |
| 입력 | 칸 아래 이유, 값은 그대로(SPEC-008) |
| 대상 | 없는 방 → 404 안내 |
| 상태 변화 | 마감 → #stale, 8명 → #error |
| 반복 | 버튼이 꺼지고, 다시 보내도 참여자는 하나(SPEC-007) |
| 동시성 | 7명 방에 두 사람이 동시에 입장하면 늦은 사람은 409 `room_full`(#error) |
| 한도 | G-3 |
| 외부 | G-4 |
| 노출 | 닉네임은 본인 화면에만(03 A-3) |
| 화면 상태 | 키보드 위에 [들어가기]. 다섯 상태 모두 360px·430px 와이어프레임 |
| 해당 없음 | 빈 결과, AI 답 |

## 규칙

- 닉네임은 앞뒤 공백을 지운 뒤 1~10자, 금칙어·줄바꿈·제어 문자 없음(SPEC-008).
