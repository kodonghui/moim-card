# SCR-011 지난 카드

경로 `/past-cards` · 누가: 확인된 사용자(자기 지난 카드만) · 흐름: FL-011 · SPEC: SPEC-027

목적: 내가 응답한 방의 최종 카드 요약을 최근 순으로 다시 보고 하나를 골라 자세히 봐요. (FL-011)

## 데이터

| 데이터 | 출처 |
| --- | --- |
| 요약: 모임 이름, 테마 이름, 기준 응답 수, 다음 행동, 확정일, 문항 8개 | API-013 `pastCards[]`(`pastCardId`, `gatheringName`, `themeName`, `basedOnCount`, `nextAction`, `finalizedAt`, `items`) |
| 다음 쪽 | API-013 `nextCursor`(20개씩) |

## 동작

| 동작 | 결과 | 실패 |
| --- | --- | --- |
| 요약 하나 누름 | 그 요약을 메모리에 두고 SCR-012로 가요 | 없음(화면 이동만) |
| [더 보기] | `cursor`로 다음 20개를 붙여요(W-11) | 목록 끝에 "더 불러오지 못했어요"와 [다시 시도], 받은 목록은 그대로 |
| [방 만들기](빈 목록) | SCR-003으로 가요 | 없음(화면 이동만) |

## 상태

| 상태 | 사용자가 보는 것과 할 수 있는 것 | 이 응답에서 |
| --- | --- | --- |
| SCR-011#normal | 줄마다 모임 이름, 테마 · "11월 28일 · 3명 기준", 다음 행동 한 줄. `nextCursor`가 있으면 맨 아래 [더 보기] | API-013#200(`one-page`) |
| SCR-011#loading | 회색 줄 3개(G-8). [더 보기] 중에는 버튼에 진행 표시 | API-013 요청 중 |
| SCR-011#empty | "아직 지난 카드가 없어요", "방이 마감되면 여기에 남아요", [방 만들기] | API-013#200(`empty`) |
| SCR-011#error | 첫 쪽 실패: "잠시 뒤 다시 해 주세요"와 [다시 시도]. 다음 쪽 실패: 목록 끝에 "더 불러오지 못했어요"와 [다시 시도] | API-013#400, API-013#default |
| SCR-011#permission | G-1, G-2 | API-013#401, API-013#403 |

## 해당하지 않는 상태

- stale: 요약은 확정 뒤 바뀌지 않고, 화면을 열 때마다 첫 쪽부터 다시 불러와요. 새로 마감된 방은 다음에 열 때 맨 위에 보여요.

## 응답과 상태

| 응답 | 코드 | 상태 | 화면이 하는 일 |
| --- | --- | --- | --- |
| API-013#200 | one-page, empty | normal 또는 empty | 첫 쪽이 0개면 empty |
| API-013#400 | validation_failed | error | `cursor`가 틀림은 앱 버그예요. 오류 보고에 남기고 첫 쪽부터 다시 불러와요 |
| API-013#401 | unauthenticated | permission | G-1 |
| API-013#403 | origin_not_allowed | permission | G-2 |
| API-013#default | internal, route_not_found, method_not_allowed | error | G-4 |

## 경우의 종류

| 종류 | 화면에 보이는 것 |
| --- | --- |
| 접근 | 내 지난 카드만 와요(서버가 걸러요) |
| 대상 | 내 데이터를 지운 뒤에는 0개(#empty) |
| 한도 | 20개씩, [더 보기] |
| 외부 | 다음 쪽 실패는 받은 목록을 지키고 끝에만 안내 |
| 노출 | 닉네임·방 코드 없음(SPEC-027) |
| 빈 결과 | #empty |
| 화면 상태 | 다섯 상태 모두 360px·430px 와이어프레임 |
| 해당 없음 | 입력, 상태 변화, 반복(읽기만 함), 동시성, AI 답 |

## 규칙

- 방이 만료돼도 요약은 남아요(DEC-009). 확정일은 기기 시간대로 "11월 28일"처럼 보여 줘요.
