# SCR-013 내 데이터 지우기

경로 `/me/delete` · 누가: 확인된 사용자(자기 데이터만) · 흐름: FL-012 · SPEC: SPEC-028, SPEC-029

목적: 지워지는 것과 남는 것을 보고 확인하면 내 데이터를 지워요. (FL-012)

## 데이터

| 데이터 | 출처 |
| --- | --- |
| 지워지는 것: 응답 수, 닉네임 수, 알림 신청 수, 지난 카드 수, 사용자 ID | API-014 `responseCount`, `nicknameCount`, `notificationSubscriptionCount`, `pastCardCount` |
| 마감되는 방: 내가 방장인 열린 방 수 | API-014 `openHostedRoomCount` |
| 남는 것: 내 응답이 들어간 확정된 최종 카드 수(이름 없는 수) | API-014 `retainedFinalCardCount` |

## 동작

| 동작 | 결과 | 실패 |
| --- | --- | --- |
| [지우기] | 확인 창(#confirm)을 띄워요 | 없음(확인 창만) |
| 확인 창 [지우기] | API-015(요청 ID 함께) → #done. 이 화면의 기록을 바꿔 끼워 뒤로가기는 미니앱을 닫아요 | "지우지 못했어요. 아무것도 지우지 않았어요"와 [다시 시도](같은 요청 ID) |
| 확인 창 [취소] | 아무것도 지우지 않고 창을 닫아요 | 없음 |
| [미니앱 닫기](#done) | 미니앱을 닫아요 | 없음 |
| [처음 화면으로](#done) | SCR-001로 가요. 이때 새 사용자로 확인돼요 | SCR-001의 실패를 따라요 |

## 상태

| 상태 | 사용자가 보는 것과 할 수 있는 것 | 이 응답에서 |
| --- | --- | --- |
| SCR-013#normal | "지우면 이것들이 사라져요": 응답 3개, 닉네임 3개, 알림 신청 1개, 지난 카드 2개, 사용자 ID. "남는 것": "확정된 최종 카드 2개의 이름 없는 수". 방장인 열린 방이 있으면 "내가 만든 열린 방 1개는 바로 마감돼요". 맨 아래 [지우기] | API-014#200(`host-of-open-room`) |
| SCR-013#loading | 목록 자리에 회색 줄(G-8). 지우는 중에는 확인 창의 [지우기]에 진행 표시, [취소]가 꺼져요(G-7) | API-014 요청 중, API-015 요청 중 |
| SCR-013#empty | 지울 응답·알림 신청·지난 카드가 없어요: "지울 응답과 알림 신청이 없어요. 사용자 ID는 지워요"와 [지우기] | API-014#200(`nothing`) |
| SCR-013#error | 현황 실패: "잠시 뒤 다시 해 주세요"와 [다시 시도]. 지우기 실패: 확인 창을 닫고 "지우지 못했어요. 아무것도 지우지 않았어요"와 [다시 시도] | API-014#default, API-015#400, API-015#429, API-015#default, 시간 초과 |
| SCR-013#permission | G-1(현황), G-2 | API-014#401, API-015#401, API-014#403, API-015#403 |
| SCR-013#confirm | 확인 창: "내 데이터를 지울까요?", "지운 것은 되돌릴 수 없어요", [지우기]·[취소] | |
| SCR-013#done | "지웠어요"와 "다시 쓰면 새 사용자로 시작해요". [미니앱 닫기](주 버튼), [처음 화면으로] | API-015#204 |

## 해당하지 않는 상태

- stale: 현황은 화면을 열 때 불러오고, 지우기는 그 순간의 내 데이터 전체에 해요. 그사이 수가 바뀌어도 지우는 범위는 같아요.

| 응답 | 코드 | 상태 | 화면이 하는 일 |
| --- | --- | --- | --- |
| API-014#200 | host-of-open-room, nothing | normal 또는 empty | 지울 응답·알림 신청·지난 카드가 모두 0이면 empty |
| API-014#401 | unauthenticated | permission | G-1 |
| API-014#403 | origin_not_allowed | permission | G-2 |
| API-014#default | internal, route_not_found, method_not_allowed | error | G-4 |
| API-015#204 | | done | 세션 토큰과 기기의 고른 답을 지우고 #done |
| API-015#400 | invalid_request | error | G-5 |
| API-015#401 | unauthenticated | permission | G-1 뒤 같은 요청 ID로 다시. 이미 지운 뒤면 서버가 204를 돌려줘요(R-8) |
| API-015#403 | origin_not_allowed | permission | G-2 |
| API-015#429 | rate_limited | error | G-3 |
| API-015#default | internal, route_not_found, method_not_allowed | error | "지우지 못했어요. 아무것도 지우지 않았어요", 같은 요청 ID로 [다시 시도] |

## 경우의 종류

| 종류 | 화면에 보이는 것 |
| --- | --- |
| 접근 | 내 데이터만. 확인 안 됨은 G-1 |
| 상태 변화 | 방장인 열린 방은 지울 때 마감돼요(미리 알림) |
| 반복 | 확인 창의 버튼이 꺼지고, 다시 보내도 결과는 하나(이미 지웠으면 204) |
| 동시성 | 지우는 중 같은 방에 다른 응답이 와도 서버가 C-4로 처리해요. 화면은 결과만 보여요 |
| 한도 | G-3 |
| 외부 | 실패하면 하나도 지우지 않은 상태라고 알려요(SPEC-029) |
| 노출 | 다른 참여자 정보가 없어요 |
| 빈 결과 | #empty(사용자 ID는 지움을 알림) |
| 화면 상태 | 일곱 상태 모두 360px·430px 와이어프레임 |
| 해당 없음 | 입력, 대상, AI 답 |

## 규칙

- 지운 뒤 자동으로 SCR-001로 가지 않아요. 가면 곧바로 새 사용자가 만들어져서예요. 사용자가 [처음 화면으로]를 누를 때만 가요(08 질문 2, FL-012 "지워졌어요 안내"를 바꿈).
