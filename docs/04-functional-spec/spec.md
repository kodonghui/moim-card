# 모임 합의 카드(가칭): 기능 명세 (04)

상태: **명세 고정, 체크포인트 통과**(2026-11-28): SPEC-001~038은 DEC-016·017(오랑이 위임), SPEC-024~026 확정과 SPEC-039는 DEC-018·019(사용자님)예요. 06 API 전 사실 확인(F-1~F-7)으로 C-5, SPEC-002, SPEC-018, SPEC-024, SPEC-025를 고쳤어요(DEC-020, 근거 DEC-016). 06 체크포인트 답으로 SPEC-025·026(마지막 응답의 알림, DEC-024)과 SPEC-039 [노출](방 코드는 화면에 없고 기기 로그에 남기지 않음, DEC-025)을 고쳤어요. 변경 절차로 SPEC-012(성향 계산 규칙과 한 줄 설명)와 SPEC-031(높은 쪽 선택지, 성향 문구 7개)을 고쳤어요(DEC-039, 오랑이 위임). 체크포인트 질문은 [checkpoint-04.md](checkpoint-04.md)에 있어요. 입력은 [02 요구사항](../02-prd/requirements.md)(REQ-001~084, 승인 main `20d6423`, 변경 DEC-018·019), [03 사용자 흐름](../03-user-flow/README.md)(FL-001~016, 승인 DEC-015·018), [01 용어집](../01-domain/domain.md#7-용어집)(TERM-001~042)이에요.

- 행 하나는 동작 하나예요. 출처 칸에 REQ와 FL을, 예외 칸에 경우의 종류를 대괄호로 적어요. 종류: **[접근]** 누가 할 수 있나 · **[입력]** 값의 한계 · **[대상]** 없거나 지워진 대상 · **[상태]** 상태가 허용하는 변화 · **[반복]** 같은 요청이 두 번 · **[동시성]** 두 요청이 한꺼번에 · **[한도]** 요청·비용 한도 · **[외부]** 토스 API·SDK 실패 · **[노출]** 결과에 넣지 않는 것 · **[빈 결과]** 비었을 때 · **[화면]** 사용자에게 알릴 것(모양은 08 단계).
- 인수 조건은 Given(주어진 상태) · When(할 때) · Then(그러면)으로 써요. 12 QA가 이 문장으로 테스트를 만들어요.
- 상태: `active`(이 초안에서 정함) · `질문 대기`(체크포인트 질문의 답에 따라 바뀜) · `removed`/`deferred`(빠지면 번호를 다시 쓰지 않고 표시만 바꿈).
- 이름은 01 용어집을 따라요. 용어집에 없는 말 세 개(모임 이름, 지난 카드, 금칙어 목록)는 02 4.4절 그대로예요.
- AI 호출: 이 앱은 AI 모델을 부르지 않아요(02 2절, 생성형 AI 결과는 범위 밖). 그래서 AI 호출 항목이 없어요.

## 1. 공통 규칙

모든 SPEC 행에 걸려요. 행의 예외 칸은 공통 규칙과 다른 것만 적고, 같은 것은 "C-n"으로 가리켜요.

| ID | 규칙 | 출처 |
| --- | --- | --- |
| C-1 | **사용자 확인.** 사용자를 밝히는 모든 요청은 서버가 확인한 사용자 ID로만 처리해요. 확인 방법은 SPEC-002예요(DEC-017: 세션 토큰). 확인이 안 되면 401과 "다시 확인이 필요해요"를 돌려주고 아무것도 읽거나 쓰지 않아요. 화면은 FL-001의 확인 단계로 돌아가요. | REQ-041 |
| C-2 | **연결 실패·서버 오류.** 화면은 사용자가 고르거나 적은 값을 지우지 않고 [다시 시도]를 줘요. 서버는 오류 코드만 돌려주고 내부 내용(스택, SQL, 토스 응답 원문)은 넣지 않아요. 요청이 10초 안에 끝나지 않으면 화면이 실패로 다뤄요. | REQ-067 |
| C-3 | **같은 요청 두 번.** 상태를 바꾸는 요청(방 만들기, 입장, 응답 제출, 마감, 알림 신청, 내 데이터 지우기)은 화면이 만든 요청 ID를 함께 보내요. 서버는 같은 사용자의 같은 요청 ID에 24시간 동안 첫 결과를 다시 돌려줘요. 입장·제출·마감은 요청 ID가 달라도 상태 규칙 때문에 한 번만 일어나요. | AI |
| C-4 | **두 요청이 한꺼번에.** 방 상태(열림 → 마감)와 응답 완료 수는 D1의 한 트랜잭션 안에서 조건을 걸어 바꿔요. 먼저 커밋한 요청이 이기고, 뒤의 요청은 바뀐 상태를 기준으로 답해요. | AI |
| C-5 | **방 코드.** 서버가 무작위로 만든 10자(헷갈리는 0·O·1·I·L을 뺀 31자, 약 49.5비트)예요(글자 수 바로잡음 DEC-020: 영문 대문자 26자와 숫자 10자에서 5자를 빼면 31자). 형식이 틀린 코드와 없는 코드는 같은 응답("없는 방")을 받아 방이 있는지 떠볼 수 없어요. 마감된 방은 링크만 있으면 누구나 최종 카드를 보므로(DEC-013) 코드는 추측할 수 없어야 해요. | REQ-052, DEC-013, AI |
| C-6 | **한도.** 서버는 토스 API 호출을 사용자당 분당 20건, 미니앱당 분당 3,000건 안으로 세요(REQ-069). 넘으면 부르지 않고 429를 돌려줘요. AI가 정한 보호 한도: 방 만들기는 사용자당 하루 30개, 그 밖의 쓰기 요청은 사용자당 분당 60건이에요. 넘으면 429와 "잠시 뒤 다시 해 주세요"를 돌려주고 아무것도 바꾸지 않아요(요구사항 없음, 4절). | REQ-069, AI |
| C-7 | **넣지 않는 것.** 어떤 응답·로그·링크에도 사용자 식별키 원문(알림 신청의 암호문 포함), 인증 코드, 세션 토큰, 다른 참여자의 사용자 ID·닉네임·개별 응답을 넣지 않아요. 카드·방 소개·응답 현황은 수만 담아요. 서버 로그의 사용자는 사용자 ID의 해시 앞 8자로만 적어요. | REQ-021, REQ-042, REQ-052, REQ-074 |
| C-8 | **시각.** 서버는 UTC로 저장하고 계산해요. 보관 기간 30일은 방을 만든 시각부터 30×24시간이에요. | REQ-047 |
| C-9 | **오래된 화면.** 카드·방 소개·응답 현황은 화면을 열 때, 미니앱으로 돌아올 때, [새로고침]을 누를 때 다시 불러와요. 실시간 연결이나 주기적 폴링은 하지 않아요. 화면에는 "○시 ○분 기준"을 적어요. | REQ-067, AI |
| C-10 | **화면 상태.** 각 행의 [화면] 항목은 알릴 내용만 정해요. 요청이 1초를 넘으면 불러오는 중 표시를 보여요. 모양은 08 화면 상태에서 정해요. | REQ-067 |
